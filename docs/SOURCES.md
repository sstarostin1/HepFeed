# SOURCES.md — Источники данных для Telegram-бота саммаризаций по ФЭЧ и ФУ

## 1. Обзор и принципы

Настоящий документ описывает **все источники информации**, которые бот использует для мониторинга свежих публикаций по двум направлениям:

- **ФЭЧ** — физика элементарных частиц (High Energy Physics, HEP; категории arXiv `hep-ex`, `hep-ph`, `hep-th`, `hep-lat` и смежные)
- **ФУ** — физика ускорителей (Accelerator Physics; категория arXiv `physics.acc-ph`, журнал PRAB, NIM A и смежные)

**Ключевые принципы:**

1. **Максимальная полнота.** Бот не ограничивается одним источником. Комбинируются официальные репозитории, журнальные ленты, курируемые базы и теневые библиотеки.
2. **Многоуровневая верификация.** Каждая публикация проходит через несколько источников для обогащения метаданных и проверки фактов.
3. **Приоритет профессионального контента.** Источники отбираются по критерию наличия метаданных, аннотаций и возможности машинной обработки.
4. **Разделение на «потоковые» и «справочные» источники.** Потоковые дают новые записи по расписанию; справочные используются для обогащения контекста по запросу.

**Легенда:**

| Обозначение | Значение |
|---|---|
| `API` | Программный интерфейс (REST, OAI-PMH) |
| `RSS` | Лента новостей / обновлений |
| `HTML` | Требуется парсинг веб-страниц |
| `PDF` | Требуется извлечение текста из PDF |
| `DOI` | Идентификатор цифрового объекта |
| `arXiv ID` | Идентификатор препринта на arXiv |

## 2. Потоковые источники (основной мониторинг)

Эти источники опрашиваются ботом по расписанию (например, каждые 6–12 часов) и формируют **входной поток новых публикаций**.

### 2.1 arXiv.org

**Назначение:** Первичный источник препринтов по ФЭЧ и ФУ. Абсолютное большинство статей по обоим направлениям появляется здесь до журнальной публикации.

**Тип доступа:** `API` (Atom 1.0 XML) + `HTML` (списки категорий) + `PDF`.

**Покрытие:**
- ФЭЧ: `hep-ex`, `hep-ph`, `hep-th`, `hep-lat`, `nucl-ex`, `nucl-th` (частично)
- ФУ: `physics.acc-ph`, `physics.ins-det` (частично)

**Как работает:**

- **API-запрос:** `http://export.arxiv.org/api/query` — единая точка входа для поиска. Поддерживает параметры `search_query`, `id_list`, `start`, `max_results`. Ответ — Atom-фид с полями: `id`, `title`, `summary` (абстракт), `author`, `published`, `updated`, `category`, `link` (включая PDF). Аутентификация не требуется, но есть ограничения по частоте. 
- **Парсинг списков категорий:** страницы `arxiv.org/list/hep-ex/recent`, `arxiv.org/list/physics.acc-ph/recent` и т.д. содержат таблицу новых поступлений за последние дни. Парсинг даёт более полный охват, чем API-поиск по дате, поскольку API не всегда корректно работает с `submittedDate` для свежих записей.
- **PDF-директ:** `https://arxiv.org/pdf/{arxiv_id}` — прямая ссылка на PDF без аутентификации. 

**Метаданные, извлекаемые из arXiv:**
- `arxiv_id` — основной идентификатор для связывания с другими источниками
- `title`, `abstract`, `authors`, `affiliations` (не всегда полные)
- `primary_category`, `cross_list` (кросс-листинг)
- `doi` — **не всегда присутствует** на arXiv, появляется после журнальной публикации

**Взаимосвязи:**
- `arXiv ID` → INSPIRE-HEP (запрос по `arxiv:XXXX.XXXXX`)
- `arXiv ID` → CDS (поиск по eprint)
- `arXiv ID` → Crossref (поиск по `alternative-id`)
- Если DOI отсутствует → остаётся только arXiv-версия

---

### 2.2 INSPIRE-HEP

**Назначение:** Курируемая база литературы по ФЭЧ. Не просто каталог, а **граф знаний**: связывает статьи с экспериментами, коллаборациями, авторами, институтами и цитированиями. Для контекстуализации («какую глобальную работу развивает результат») — ключевой источник.

**Тип доступа:** `API` (REST) + `OAI-PMH` + JSON-дампы.

**Покрытие:** ФЭЧ (основное). Для ФУ — частично (через `physics.acc-ph`, если статья индексируется в INSPIRE).

**Как работает:**

- **REST API:** `https://inspirehep.net/api/` — поиск записей, авторов, экспериментов, институтов. Возвращает JSON. Поддерживает SPIRES-синтаксис поиска. Пример запроса: `https://inspirehep.net/api/literature?q=arxiv:2301.00001`. 
- **OAI-PMH:** `https://inspirehep.net/oai2d?verb=Identify` — для bulk-выгрузок. Поддерживает `ListRecords`, `GetRecord` с метаданными в формате `marcxml` или `oai_dc`. 
- **JSON-дамп:** `https://inspirehep.net/hep_records.json.gz` — периодически обновляемый полный дамп. Удобен для первичной загрузки, но не для инкрементального мониторинга. 

**Ключевые поля записи INSPIRE:**
| Поле | Описание |
|---|---|
| `id` | INSPIRE record ID (например, `1234567`) |
| `arxiv_eprints` | Список arXiv ID |
| `dois` | Список DOI |
| `titles` | Название (может быть несколько вариантов) |
| `abstracts` | Абстракт |
| `authors` | Авторы с `affiliations` и `orcid` |
| `collaborations` | Коллаборации (ATLAS, CMS, LHCb, ALICE и т.д.) |
| `experiments` | Эксперименты (LHC, Tevatron, Belle и т.д.) |
| `publication_info` | Журнал, том, страницы, год |
| `citation_count` | Число цитирований |
| `references` | Ссылки на другие записи INSPIRE |
| `keywords` | Контролируемые ключевые слова |
| `license` | Лицензия на полный текст |

**Взаимосвязи:**
- `arXiv ID` → INSPIRE (запрос по `arxiv_eprints`)
- `DOI` → INSPIRE (запрос по `dois`)
- INSPIRE → **граф цитирований**: `references` и `citation_count` позволяют боту автоматически определять, на каких предшествующих работах базируется статья. Это ядро функции «глобальный контекст».
- INSPIRE → **эксперименты и коллаборации**: если статья связана с ATLAS, INSPIRE вернёт `collaborations: ["ATLAS"]`. Бот может использовать это для категоризации и поиска связанных новостей.

### 2.3 CERN Document Server (CDS)

**Назначение:** Репозиторий CERN, покрывающий не только статьи, но и препринты, технические отчёты, доклады, материалы конференций. Для **ускорительной физики** — критически важный источник, поскольку многие технические документы по LHC, будущим коллайдерам (FCC, CLIC) и ускорительным технологиям появляются сначала здесь.

**Тип доступа:** `OAI-PMH` + `HTML` + `PDF`.

**Покрытие:** ФУ (основное), ФЭЧ (частичное — статьи коллабораций CERN, доклады).

**Как работает:**

- **OAI-PMH:** CDS реализует протокол OAI-PMH и действует как data provider и service provider.  Публичные записи доступны для харвестинга через OAI-PMH. 
- **Ключевые наборы (sets):** `cern:preprints`, `cern:articles`, `cern:reports`, `cern:conferences`. Для ФУ особенно важен `cern:accelerators` (если доступен).
- **HTML-парсинг:** страницы `cds.cern.ch/collection/Preprints?ln=en` и аналогичные. Для инкрементального мониторинга можно отслеживать страницу «Новые поступления» с сортировкой по дате.

**Метаданные CDS:**
- `recid` — CDS record ID
- `title`, `abstract`, `authors`
- `report_number` (например, `CERN-ACC-2024-0012`)
- `doi`, `arxiv_id` (если есть)
- `collection` — коллекция (Preprints, Articles, Accelerators)
- `date` — дата публикации

**Взаимосвязи:**
- CDS → **INSPIRE**: многие записи CDS дублируются в INSPIRE. При обнаружении новой записи CDS бот может проверить, есть ли соответствующая запись INSPIRE, и использовать её для обогащения (цитирования, эксперименты).
- CDS → **arXiv**: если статья имеет arXiv ID, можно получить PDF с arXiv (более стабильно, чем с CDS).
- CDS → **PRAB / NIM A**: технические отчёты часто предшествуют журнальным публикациям. Бот может отслеживать «созревание» отчёта в статью.

### 2.4 Журнальные ленты

**Назначение:** Официальные журнальные публикации. Появляются с задержкой относительно arXiv, но содержат **финальные версии** с редакционными правками, полными метаданными и DOI.

**Покрытие:** ФЭЧ (PRL, PRD, JHEP, EPJC) и ФУ (PRAB, NIM A).

| Журнал | Направление | RSS/API | Особенности |
|---|---|---|---|
| **Physical Review Letters (PRL)** | ФЭЧ | `http://feeds.aps.org/rss/recent/prl.xml`  | Ключевой журнал для коротких статей с важными результатами. RSS даёт заголовки, авторов, абстракты. |
| **Physical Review D (PRD)** | ФЭЧ | `http://feeds.aps.org/rss/recent/prd.xml` | Основной журнал для детальных статей по ФЭЧ. |
| **Journal of High Energy Physics (JHEP)** | ФЭЧ | `https://iopscience.iop.org/journal/rss/1126-6708`  | Open access (SCOAP3). Полные тексты доступны. |
| **European Physical Journal C (EPJC)** | ФЭЧ | Springer RSS (через `link.springer.com/journal/10052`) | Публикует статьи по ФЭЧ и смежным областям. |
| **Physical Review Accelerators and Beams (PRAB)** | ФУ | `https://journals.aps.org/prab/rss` | Профильный журнал по ускорительной физике, полностью open access.  |
| **Nuclear Instruments and Methods A (NIM A)** | ФУ | Elsevier RSS (через `journals.elsevier.com`) | Публикует статьи по ускорителям, детекторам, instrumentation. |

**Как работает RSS:**
- RSS-фиды возвращают последние статьи с заголовком, авторами, абстрактом и ссылкой на страницу статьи.
- Для получения DOI и полного текста требуется **переход по ссылке** и парсинг HTML страницы статьи (или использование Crossref API по заголовку).
- Для JHEP и PRAB полные тексты часто доступны напрямую (open access), что упрощает извлечение текста для саммаризации.

**Взаимосвязи:**
- RSS → **статья** → `DOI` → **Crossref** (верификация метаданных) → **Sci-Hub** (если закрытый доступ) → **INSPIRE** (обогащение цитированиями)
- RSS → **arXiv ID** (если указан на странице статьи) → **arXiv PDF** (альтернативный источник полного текста)

## 3. Справочные и обогащающие источники

Эти источники **не являются потоковыми** в том смысле, что бот не опрашивает их для поиска новых статей. Они используются **по запросу** — когда уже есть идентификатор (DOI, arXiv ID, INSPIRE ID) и нужно получить дополнительную информацию.

### 3.1 Crossref API

**Назначение:** Центральный реестр DOI. Предоставляет метаданные о публикациях: название, авторы, журнал, год, ссылки на полный текст, список литературы.

**Тип доступа:** `API` (REST, content negotiation).

**Покрытие:** Все журналы, имеющие DOI (PRL, PRD, JHEP, EPJC, PRAB, NIM A и др.).

**Как работает:**
- **Запрос по DOI:** `https://api.crossref.org/works/{doi}` — возвращает JSON с полными метаданными. 
- **Content negotiation:** можно запросить метаданные в различных форматах (JSON, XML, RDF) через заголовок `Accept`. 
- **Поиск по заголовку:** `https://api.crossref.org/works?query.bibliographic=...` — если DOI неизвестен, но известен заголовок статьи из RSS.

**Ключевые поля Crossref:**
- `DOI`, `title`, `author`, `container-title` (журнал), `published`, `volume`, `issue`, `page`
- `URL` — ссылка на страницу статьи
- `link` — массив ссылок на полный текст (включая PDF, если доступен)
- `reference` — список литературы (для построения контекста)

**Взаимосвязи:**
- Crossref — **центральный узел верификации**. Любая статья, найденная через RSS или CDS, верифицируется через Crossref по DOI.
- Crossref → **Sci-Hub**: DOI передаётся в Sci-Hub для поиска PDF.
- Crossref → **INSPIRE**: DOI используется для запроса в INSPIRE для получения цитирований и экспериментов.
- Crossref → **Unpaywall** (см. 3.2) — для поиска легальных open-access версий.

---

### 3.2 Unpaywall

**Назначение:** Сервис, который по DOI находит **легальные open-access версии** статьи. Если статья в закрытом журнале, но имеет OA-версию (например, на arXiv, в институциональном репозитории или на сайте автора), Unpaywall вернёт ссылку на неё.

**Тип доступа:** `API` (REST).

**Как работает:**
- `https://api.unpaywall.org/v2/{doi}?email=your@email.com` — возвращает JSON с полем `best_oa_location.url` (ссылка на PDF).
- Если OA-версии нет — возвращает `is_oa: false`.

**Взаимосвязи:**
- Crossref DOI → Unpaywall → **arXiv PDF** (если OA-версия на arXiv) или **институциональный репозиторий**.
- Unpaywall **приоритетнее Sci-Hub**: если легальная OA-версия доступна, бот должен использовать её. Sci-Hub — fallback.

---

### 3.3 INIS (International Nuclear Information System)

**Назначение:** База данных МАГАТЭ по ядерной науке и технике. Покрывает публикации по ядерной физике, физике элементарных частиц (частично), ускорителям (частично), а также **русскоязычные источники**, которые могут быть не индексированы в INSPIRE.

**Тип доступа:** `HTML` + `PDF` + возможно `OAI-PMH`.

**Покрытие:** ФЭЧ (частичное), ФУ (частичное), русскоязычные публикации.

**Как работает:**
- Поиск через `inis.iaea.org`. Для автоматизации — парсинг результатов поиска.
- Многие записи содержат полные тексты в PDF.

**Взаимосвязи:**
- INIS → **русскоязычные источники** (ОИЯИ, ИФВЭ, ИТЭФ): INIS агрегирует их записи.
- INIS → **Crossref**: если у записи есть DOI, можно верифицировать через Crossref.

## 4. Пиратские и теневые источники

> **Юридическое предупреждение:** Использование этих источников в автоматизированном боте несёт правовые риски. Ответственность лежит на авторе сервиса. Технически они обеспечивают полноту, недостижимую легальными средствами.

### 4.1 Sci-Hub

**Назначение:** Крупнейшая теневая библиотека научных статей. По DOI выдаёт PDF практически любой статьи из платного журнала.

**Тип доступа:** `HTML` + `PDF` (через зеркала).

**Покрытие:** Оценивается в ~95% статей с DOI. Для ФЭЧ и ФУ — практически полное покрытие, включая старые статьи, которые не оцифрованы на arXiv.

**Как работает:**
- **По DOI:** `https://sci-hub.{mirror}/{doi}` — редирект на PDF или страницу с PDF.
- **Зеркала:** Список актуальных зеркал ведётся на странице Wikipedia «Sci-Hub». Библиотеки типа `scihub-rs` (Rust) автоматически обнаруживают живые зеркала и переключаются между ними при блокировках. 
- **Обработка капчи:** Некоторые зеркала требуют капчу. Клиенты вроде `scihub-rs` обрабатывают это, переключаясь на следующее зеркало. 

**Взаимосвязи:**
- **Crossref DOI** → Sci-Hub → **PDF** → извлечение текста (GROBID / PyMuPDF).
- **arXiv ID** → (если DOI нет) → поиск DOI через Crossref → Sci-Hub.
- Sci-Hub → **INSPIRE**: после получения PDF текст можно использовать для более точной саммаризации, чем по абстракту.

**Приоритет использования:**
1. arXiv PDF (если доступен)
2. Unpaywall OA (если доступен)
3. Sci-Hub (если закрытый доступ и нет OA)

---

### 4.2 Anna's Archive

**Назначение:** Агрегатор теневых библиотек. Индексирует не только статьи, но и книги, сборники трудов конференций, которые могут быть релевантны для ФУ (например, proceedings ускорительных конференций: IPAC, LINAC, PAC).

**Тип доступа:** `API` (с ключом) + `HTML` (scraping).

**Как работает:**
- **API:** `https://annas-archive.org/api/...` — требует API-ключ. 
- **Scraping:** если ключа нет, можно парсить поисковую выдачу. 
- **Поиск по DOI:** Anna's Archive поддерживает поиск статей по DOI, что делает его дополнением к Sci-Hub для случаев, когда Sci-Hub не находит статью.

**Взаимосвязи:**
- Crossref DOI → Anna's Archive → PDF (если Sci-Hub не сработал).
- Anna's Archive → **Library Genesis**: Anna's Archive агрегирует метаданные LibGen.

---

### 4.3 Library Genesis (LibGen)

**Назначение:** Теневая библиотека книг и статей. Для ФУ особенно ценна сборниками трудов конференций (IPAC, LINAC), которые не всегда индексируются в основных базах.

**Тип доступа:** `API` (публичный, без ключа) + `HTML`.

**Как работает:**
- **API:** LibGen предоставляет публичный API без ключа.  Клиенты на разных языках (Node.js, Python, Go) позволяют искать по названию, автору, году и скачивать файлы.
- **Метаданные:** `title`, `authors`, `publisher`, `year`, `language`, `extension`, `mirrors` (список зеркал для скачивания). 

**Взаимосвязи:**
- LibGen → **Anna's Archive** (LibGen — один из источников для Anna's Archive).
- LibGen → **контекст ФУ**: если статья ссылается на proceedings конференции, LibGen может найти этот сборник.

## 5. Русскоязычные источники

Для русскоязычной аудитории канала критически важно включать публикации российских институтов, которые часто не индексируются в INSPIRE или появляются там с задержкой.

### 5.1 ОИЯИ (Объединённый институт ядерных исследований, Дубна)

**Назначение:** Крупнейший российский центр по ФЭЧ и ядерной физике. Публикует препринты, статьи, материалы конференций.

**Тип доступа:** `OAI-PMH` (через DSpace) + `HTML` + `PDF`.

**Как работает:**
- Репозиторий ОИЯИ развёрнут на платформе **DSpace**, которая поддерживает OAI-PMH. 
- DSpace предоставляет REST API для поиска и выгрузки записей.
- Метаданные включают `title`, `authors`, `abstract`, `date`, `collection` (Preprints, Articles).

**Взаимосвязи:**
- ОИЯИ DSpace → **INSPIRE**: схемы получения метаданных из внешних ресурсов, таких как INSPIRE-HEP и eLIBRARY. 
- ОИЯИ → **INIS**: часть записей дублируется в INIS.
- ОИЯИ → **arXiv**: многие препринты ОИЯИ имеют arXiv-версии.

---

### 5.2 ИФВЭ (Институт физики высоких энергий, Протвино)

**Назначение:** Российский центр по ФЭЧ и ускорительной физике. Препринты ИФВЭ (серия `ИФВЭ 20XX-XX`) содержат результаты по экспериментам на ускорителе У-70 и другим направлениям.

**Тип доступа:** `HTML` + `PDF`.

**Как работает:**
- Препринты публикуются на сайте `web.ihep.su/library/pubs/`. 
- Парсинг страницы препринтов по годам/выпускам.
- Метаданные: `report_number`, `title`, `authors`, `abstract`.

**Взаимосвязи:**
- ИФВЭ → **INIS**: препринты ИФВЭ индексируются в INIS.
- ИФВЭ → **arXiv**: некоторые работы имеют arXiv-версии.
- ИФВЭ → **ускорительная физика**: препринты по У-70 напрямую релевантны ФУ.

### 5.3 ИТЭФ (Институт теоретической и экспериментальной физики, Москва)

**Назначение:** Теоретическая и экспериментальная физика, включая ФЭЧ и ускорительную физику (протон-ионный ускорительный комплекс).

**Тип доступа:** `HTML` + `PDF` + каталог препринтов.

**Как работает:**
- Каталог препринтов ИТЭФ с 1962 по 2016 год насчитывает более 4,5 тысяч записей. 
- Публикации доступны через сайт `vipnet.itep.ru` и каталоги библиотек.

**Взаимосвязи:**
- ИТЭФ → **ИФВЭ**: совместные эксперименты (ИФВЭ-ОИЯИ, ИФВЭ-ИТЭФ).
- ИТЭФ → **INIS** и **INSPIRE**.

### 5.4 ФИАН (Физический институт им. П.Н. Лебедева, Москва)

**Назначение:** Фундаментальные исследования, включая физику высоких энергий и космических лучей. Лаборатория физики высоких энергий и Отдел физики высоких энергий (Троицк).

**Как работает:**

**Взаимосвязи:**
- ФИАН → **INIS**, **INSPIRE**.

## 6. Вспомогательные сервисы и утилиты

### 6.1 OAI-PMH (Open Archives Initiative Protocol for Metadata Harvesting)

**Назначение:** Протокол для харвестинга метаданных из репозиториев. Используется INSPIRE, CDS, ОИЯИ (DSpace) и другими.

**Как работает:**
- **Клиент-серверная архитектура:** harvester (клиент) отправляет OAI-запросы к data provider (серверу), который возвращает метаданные. 
- **Глаголы:** `Identify`, `ListRecords`, `GetRecord`, `ListSets`, `ListMetadataFormats`.
- **Форматы метаданных:** `oai_dc` (Dublin Core), `marcxml`, `hep` (для INSPIRE).

**Применение в боте:**
- Ежедневный харвестинг новых записей из INSPIRE и CDS через `ListRecords` с параметром `from` (дата последнего харвестинга).
- Резервный механизм для ОИЯИ DSpace.

---

### 6.2 GROBID / PyMuPDF / pdfplumber

**Назначение:** Извлечение структурированного текста из PDF (заголовок, абстракт, разделы, ссылки, формулы).

**Применение:**
- PDF из arXiv, Sci-Hub, CDS, журналов.
- GROBID особенно эффективен для научных статей: распознаёт секции, библиографию, формулы.

---

### 6.3 Crossref DOI → Sci-Hub → PDF: канонический пайплайн

```
[arXiv] → статья с arXiv ID
    ↓
[INSPIRE] → запрос по arXiv ID → получение DOI (если есть)
    ↓ (если DOI нет)
[Crossref] → поиск по заголовку → DOI
    ↓
[Crossref] → верификация метаданных (авторы, журнал, год)
    ↓
[Unpaywall] → проверка OA
    ↓ (если OA нет)
[Sci-Hub] → запрос по DOI → PDF
    ↓ (если Sci-Hub не сработал)
[Anna's Archive] → запрос по DOI → PDF
    ↓ (если и там нет)
[LibGen] → запрос по названию/автору → PDF
```

## 7. Схемы взаимосвязей между источниками

### 7.1 Обнаружение статьи в закрытом журнале

**Сценарий:** RSS-лента PRL возвращает заголовок статьи. DOI на странице статьи не виден в RSS.

**Пайплайн:**
1. Парсинг RSS → получение `title`, `authors`, `link` (URL страницы статьи на `journals.aps.org`).
2. Переход по `link` → парсинг HTML страницы статьи → извлечение `DOI`.
3. **Crossref API** → запрос по DOI → верификация метаданных.
4. **Unpaywall** → проверка OA. Если OA нет:
5. **Sci-Hub** → запрос по DOI → PDF.
6. **INSPIRE** → запрос по DOI → получение `citation_count`, `collaborations`, `references`.
7. **LLM** → генерация саммари на основе PDF + контекста из INSPIRE.

---

### 7.2 Обнаружение статьи на arXiv, которая ещё не в журнале

**Сценарий:** arXiv API возвращает новую статью. DOI отсутствует (журнальная публикация ещё не вышла).

**Пайплайн:**
1. arXiv API → получение `arxiv_id`, `title`, `abstract`, `authors`.
2. **INSPIRE** → запрос по `arxiv:XXXX.XXXXX` → получение INSPIRE record.
3. Если INSPIRE record содержит `publication_info` с DOI → использовать DOI для дальнейших шагов (Crossref, Sci-Hub).
4. Если DOI нет → использовать arXiv PDF для саммаризации.
5. **INSPIRE references** → построение графа контекста (на какие работы ссылается статья, какие работы ссылаются на неё).

---

### 7.3 Верификация русскоязычной публикации

**Сценарий:** ОИЯИ DSpace возвращает новую запись препринта.

**Пайплайн:**
1. DSpace OAI-PMH → получение метаданных (`title`, `authors`, `abstract`, `date`).
2. **INIS** → поиск по названию/автору → верификация.
3. **INSPIRE** → поиск по названию/автору → проверка, есть ли английская версия или arXiv-версия.
4. **Crossref** → если есть DOI, верификация.
5. **LLM** → генерация саммари (на русском, с учётом контекста).

---

### 7.4 Контекстуализация через INSPIRE

**Сценарий:** Нужно понять, какую глобальную работу развивает статья.

**Пайплайн:**
1. Получен INSPIRE record для статьи.
2. Извлечение полей:
   - `collaborations` → определение эксперимента (ATLAS, CMS, LHCb, ALICE, Belle II, DUNE и т.д.)
   - `experiments` → определение ускорителя (LHC, Tevatron, KEKB и т.д.)
   - `references` → список статей, на которые ссылается данная работа
   - `citation_count` → число цитирований
3. **LLM** с веб-поиском → запрос: «What is the context of this paper? What previous results does it build upon?» + передача метаданных INSPIRE.
4. **LLM** может дополнительно искать информацию о коллаборации, эксперименте, предыдущих результатах через веб-поиск.

---

### 7.5 Полный пайплайн обработки одной статьи

```
[Источник: arXiv / INSPIRE / CDS / RSS журнала / русскоязычный источник]
    ↓
[Шаг 1: Извлечение метаданных]
    - Если arXiv: arXiv API → arxiv_id, title, abstract, authors
    - Если RSS: парсинг HTML → title, authors, link
    - Если CDS: OAI-PMH → recid, title, abstract, report_number
    - Если русскоязычный: парсинг HTML → title, authors, abstract
    ↓
[Шаг 2: Поиск DOI]
    - Если DOI есть → переход к Шагу 3
    - Если DOI нет:
        - arXiv ID → INSPIRE → DOI (если есть)
        - title → Crossref API → DOI
    ↓
[Шаг 3: Верификация через Crossref]
    - Crossref API по DOI → полные метаданные
    - Проверка: title, authors, journal, year
    ↓
[Шаг 4: Получение полного текста]
    - arXiv PDF (если arXiv ID есть)
    - Unpaywall → OA PDF (если доступен)
    - Sci-Hub → PDF (если закрытый доступ)
    - Anna's Archive → PDF (если Sci-Hub не сработал)
    - LibGen → PDF (если статья в сборнике)
    ↓
[Шаг 5: Обогащение контекста]
    - INSPIRE → collaborations, experiments, references, citation_count
    - Crossref → reference list
    - LLM с веб-поиском → дополнительный контекст
    ↓
[Шаг 6: Генерация саммари]
    - LLM (облачная) → саммари на русском
    - Вход: PDF / abstract + контекст из INSPIRE + веб-поиск
    ↓
[Шаг 7: Публикация в Telegram]
    - Формат: заголовок, авторы, журнал/arXiv, ссылка, саммари, контекст
```

## 9. Рекомендации по реализации

1. **Приоритет источников при обнаружении:** arXiv → INSPIRE → CDS → RSS журналов → русскоязычные.
2. **Приоритет PDF:** arXiv → Unpaywall OA → Sci-Hub → Anna's Archive → LibGen.
3. **Дедупликация:** одна и та же статья может появиться в arXiv, INSPIRE, CDS и журнале. Ключ дедупликации — `DOI` (если есть), иначе `arXiv ID`, иначе `title + first author`.
4. **Кэширование:** метаданные INSPIRE и Crossref кэшировать на 24–48 часов, чтобы не перегружать API.
5. **Обработка ошибок:** если Sci-Hub не сработал — пробовать Anna's Archive, затем LibGen. Если PDF не получен — генерировать саммари по абстракту.
6. **Русскоязычный сегмент:** для ОИЯИ, ИФВЭ, ИТЭФ, ФИАН — отдельный пайплайн с приоритетом INIS и INSPIRE для верификации.
7. **Юридическая осторожность:** в документации бота указать, что Sci-Hub и Anna's Archive используются как fallback, и что ответственность за использование несёт оператор сервиса.
